一、技术栈

运行时 Node.js v24（仅内置模块）
协议 MCP / JSON-RPC 2.0
传输 stdio（换行分隔） + SSE
浏览器自动化 CDP over 原生 WebSocket
网络 原生 fetch / WebSocket（无 axios）
数据 JSON 文件黑板 + JSONL run-log
前端 自包含 HTML + 原生 JS（无框架）
Web 服务 node:http（无 Express）
Worker WorkBuddy / CodeBuddy CLI / 元宝 / VSCode

设计取向：零 npm 依赖、不联网安装、不引入编排框架（LangGraph/CrewAI/AutoGen/Playwright/Puppeteer）；仅用 Node 内置模块 + 本机已有程序（Edge / CLI）搭最小闭环。

四、一次 run_chain 的数据流

WorkBuddy 经 MCP 调 run_chain{fresh} → core 触发 chain.js。
chain.js 读 pipeline.js 的“当前流水线·当前版本”得到步骤序列。
每步：把 roles.js 身份卡 + 上游 result.md 注入下游 goal，写 tasks/<id>/task.json。
core.dispatch 先过 safety（命中不可逆→拦截；操作型腿→待确认）。
再过 cost（超预算→改走单 agent 回落）。
adapters 按 role 调对应 worker（元宝/CodeBuddy/VSCode），worker 产结果。
写 result.md + 追 run-log.jsonl + 记 cost.json；做上下文交接完整性校验。
遇待确认→返回 pending，WorkBuddy approve_task 后续跑；遇失败→repair 生成修复提示词并停链上报。
指挥台 cockpit 实时读 runs/status 展示 KPI、链、成本、待确认、诊断。

五、进程与端口拓扑

指挥台控制台:8770（cockpit-server）
SSE MCP 备用:18766（sse-server）
Edge CDP 调试:9333（元宝登录态）
stdio MCP由 WorkBuddy 拉起 mcp-adapter
一键启动：start.ps1 设好 RELAY_* env → 起 Edge 登录态 + 指挥台 + SSE + 当日快照；-Stop 按端口反查真实 PID 停止；位置无关、UTF-8 BOM。
端口被旧实例占用时：脚本探针该端口的实例（/api/system、/info），发现是旧代码则自动让位到下一个空闲端口；要回到标准端口需用管理员权限执行 -Stop。

六、关键设计

主题做法
差异化：交接质量结构化任务契约 + 上游产物压成结构化交接块（来源/指纹/摘要/内容上限）+ 指纹校验完整性（防“传话游戏”）
上下文生命周期交接默认截断 4000 字；依赖失效：上游产物变 → 下游自动重跑；断点续跑跳过的步从 run-log 回填真实耗时/token/成本
角色协作persona 身份卡注入 worker 提示词；流水线按业务事项编排、版本化可回滚
动态编排（模型可改链）MCP 暴露 11 工具，含 list_pipelines/save_pipeline/use_pipeline/set_pipeline_version → 主控(harness)能自编链、存版本、切链、回滚
安全红线不可逆/高危词直接拦截；操作型腿默认人工确认；分类前剥离注入上下文防误拦
成本生死线优先用 worker CLI 的真实 usage（CodeBuddy 已接通），无则字符估算；按项目分账、超预算自动降级单 agent
可观测 / 接管run-log + status + 指挥台四视图；断点续跑、逐步重跑/忽略/批准、失败只读诊断
端口与实例可辨start.ps1 探针端口上的实例（/api/system、/info 返回“跑的是哪份代码”），旧实例自动让位到下一个空闲端口；指挥台显示运行时代码路径/端口/启动时间
元宝零依赖自动化原生 WebSocket 驱动 Edge CDP；ensureInput 自愈“追问/澄清”子态；失败即停链上报
CodeBuddy 编排headless -p --max-turns 1 --tools "" --output-format json --port <空闲> + stdin 传 prompt；取用顺序 显式 > PATH > 内置兜底
自愈与幂等端口冲突自动换空闲重试；断点续跑跳过已 ok；停链生成修复提示词
